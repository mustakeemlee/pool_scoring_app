# CLAUDE.md

Guidance for Claude Code working in this repository. For how to run the app, see `README.md`. For the full design history, see `docs/superpowers/specs/` and `docs/superpowers/plans/`.

## What this is

A pool league player ranking/grading app (Elo/Glicko-2 hybrid rating engine, grade bands, weekly admin workflow, statistics/odds) — an amateur-league scoring tool, **not** a gambling product. One application, built in phases (rating engine → backend API → frontend → self-hosting) that are development history, not separate apps or optional layers.

## Stack

- **Rating engine**: TypeScript, pure functions, in `src/rating/`.
- **Backend**: Supabase (Postgres, GoTrue, PostgREST, Deno Edge Functions).
- **Frontend** (`web/`): React 18 + Vite + TypeScript + Tailwind + shadcn/ui + TanStack Query v5 + React Router v6 + Recharts. Own `package.json`, own test suite.
- **Testing**: Vitest everywhere. Backend/db tests hit real Postgres/real HTTP endpoints — this codebase prefers real behavior over mocks wherever feasible.

## Conventions this codebase actually enforces

- **Real Postgres transactions for every write Edge Function.** `supabase/functions/_shared/dbTransaction.ts` opens a direct `postgres` (postgres.js) connection via `SUPABASE_DB_URL` — required because PostgREST/supabase-js has no multi-statement transaction API. Any new write path needs the same treatment: acquire row locks in **ascending player-id order** (prevents deadlocks between concurrent requests naming the same two players in either order), re-check any state a lock could have made stale, and coerce every `numeric` column read through `postgres.js` with `Number(...)` before doing arithmetic on it — `postgres.js` returns `numeric` as a string, not a number, and silent string concatenation is an easy, real bug here (bit us during Phase A).
- **`requireAdmin()` is the sole, sufficient authorization gate** for every admin write, verified live (rejects missing/invalid/non-admin tokens on every request, no cached admin status). Don't assume the self-hosted edge-runtime does any independent JWT verification — it doesn't, by design; `requireAdmin()` alone is what's real.
- **Errors surface verbatim to the client, never swallowed or reworded.** This is deliberate throughout the backend and frontend. If you're tempted to catch-and-generalize an error message, don't.
- **TanStack Query keys always come from `web/src/lib/queryKeys.ts`.** Never write an inline literal key array in a hook or an `invalidateQueries` call — this exact mistake (a mutation forgetting to invalidate a key another page depends on) has recurred multiple times across this project's history. When a mutation changes data that could affect a player's profile broadly (a week close, a correction), invalidate the whole `['playerProfile']` prefix rather than enumerating specific player IDs.
- **`AdminRouteGuard` is a UX convenience, not the security boundary.** Real enforcement is server-side (RLS + `requireAdmin()`). Don't add client-side checks under the assumption they're load-bearing.
- **Migrations are append-only.** If you need to change something a past migration did, write a new migration.

## Testing discipline

- `npm test` (repo root) runs unit (`src/rating`) + integration (`src/db`) + api (`src/api`). The api suite needs the local Supabase stack running (`npm run supabase:start`) and, for anything touching a write Edge Function, `supabase functions serve` (or the stack's own edge-runtime) actually serving current code.
- `cd web && npm test` runs the frontend suite independently.
- **Flaky-looking failures under concurrent/heavy load are common on this machine and are usually not real regressions** — this repo's test suite is Docker- and HTTP-heavy, and this session has repeatedly seen 5000ms timeouts and even a Supabase CLI telemetry-file EPERM race that were pure environmental noise. Before treating a failure as a real bug: re-run the specific failing file alone. If it passes in isolation, it was contention, not a regression.
- For a genuine root-cause investigation (not just "rerun and see"), use the `systematic-debugging` skill rather than guessing at fixes.

## Windows / OneDrive quirks (this machine specifically)

- `core.autocrlf=true` will silently corrupt shell script shebangs on checkout unless `.gitattributes` pins `*.sh text eol=lf` (already set — keep it that way for any new `.sh` file).
- Recurring harmless noise you can ignore: `socket_is_stale: socket: No buffer space available` (SSH-agent/Windows resource noise) and `error: failed to delete '.git/worktrees/...': Permission denied` on commits (a stale worktree metadata dir OneDrive has locked — git still deregisters the worktree correctly; only the empty directory stub fails to delete).
- `git stash` can silently fail to actually revert the working tree on this machine (the stash object is created correctly, but the "restore working tree to HEAD" step can no-op under an OneDrive file lock) — after any stash, verify with `git status`/`git diff HEAD` rather than assuming the working tree is clean.
- Docker health-check timing is tight on this machine; a container reporting unhealthy despite clean logs is often worth one retry before treating it as broken.

## Workflow used for every phase of this project

brainstorm (superpowers:brainstorming) → design spec (`docs/superpowers/specs/`) → implementation plan (`docs/superpowers/plans/`) → subagent-driven-development (fresh implementer per task, fresh reviewer per task, whole-branch review at the end) → finish the branch. This is not ceremony for its own sake — it's caught real, subtle bugs (concurrency races, migration robustness against non-empty databases, security gaps) at every stage it's been used. Follow it for new features and nontrivial infra changes; a small, obviously-correct fix doesn't need the full ceremony.
